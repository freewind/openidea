本文件由 `src/platform/keymaps/intellij-classic-macos.ts` 逐条导出，供人工核对。**只做导出，不代表这些键位正确。**

## 重要更正：macOS 上 Ctrl 与 Meta 会互换

IDEA 在 macOS 上加载 `$default.xml` 时，会把键位里的 Ctrl 与 Meta 互换（`MacOSDefaultKeymap.kt` 的 `mapModifiers`，见 `platform/platform-impl/src/com/intellij/openapi/keymap/impl/MacOSDefaultKeymap.kt`；本机 jar 里同名类字节码一致）。`Mac OS X.xml` 自己写的键位不互换。

所以本表里凡「只继承 `$default.xml`」且写 `Ctrl` 的条目（**129 条**，备注已标 ⚠），IDEA 里实际显示为 ⌘，preset 现在的 Ctrl 值很可能应为 `Meta`。

实证：freewind keymap（parent 为 Mac OS X，即 Classic）里 Go to File 显示 ⇧⌘N，而 `$default.xml` 写的是 `control shift N`。

## 复核结论（先看这里）

### 根因问题：漏做 Ctrl↔Meta 互换（影响 129 条）

preset 把 `$default.xml` 的 Ctrl 原样当成 Ctrl，但 macOS 上 IDEA 会互换 Ctrl 与 Meta。受影响的 129 条在表格备注里标了 ⚠，最典型的是 `navigate.gotoFile` 现在是 `Ctrl+Shift+N`、应为 `Meta+Shift+N`，`navigate.gotoClass` 现在 `Ctrl+N`、应为 `Meta+N`。

### 确定错（1 条）

- `vcs.changelist.move` = `Alt+Shift+M`：`Mac OS X.xml` 把 `ChangesView.Move` 和 `Vcs.MoveChangedLinesToChangelist` 都列出来却不给键位，即解绑；preset 却把 `$default` 的 `Alt+Shift+M` 填了回去，应为「无绑定」。

### 疑似错（撞键或语义错位，9 条）

- `terminal.new` = `Ctrl+Shift+T`：classic 里这个键位属 `GotoTest`，和 `navigate.gotoTest` 撞车。
- `code.pasteFromHistory` = `Ctrl+Shift+V`：classic 里属 `PasteMultiple`，`PasteFromHistory` 本身没有键位。
- `code.addCaretNextOccurrence` = `Ctrl+G`：classic 里 `Ctrl+G` 属 `GotoLine` / `SelectNextOccurrence`，和 `navigate.gotoLine` 撞车。
- `image.actualSize` = `Ctrl+/`：classic 里属 `CommentByLineComment`，和 `code.commentLine` 撞车。
- `project.newFile`、`code.generate`、`db.new`、`services.addService`、`github.createPullRequest` = `Alt+Insert`：classic 里 `Generate` 和 `NewElement` 已被 `Mac OS X.xml` 改成 `Ctrl+N` / `Ctrl+Enter`，`Alt+Insert` 只剩 `FileChooser.NewFolder`；这 5 条共用一个键位。

### 无依据（`$default` 物理键位兜底，共 49 条）

两个 XML 里都找不到对应 action，见下面的 C 节。最典型的是 `vcs.commit` = `Ctrl+K`、`vcs.push` = `Ctrl+Shift+K`、`vcs.commitAndPush` = `Ctrl+Alt+K` —— IDEA classic 里提交、推送根本没有键位；`code.unfold` = `Ctrl+=`、`code.unfoldAll` = `Ctrl+Shift+=` 同样没有出处。

### 代码内依据自身的问题

- `intellijClassic.test.ts:45` 说 `refactor.thisMenu` 被 `Mac OS X.xml` 解绑，对应的 IDEA action 写的是 `RefactorThis`；但两个 XML 里都没有 `RefactorThis`，注解的 action id 是错的（`refactor.thisMenu` 为空数组这件事本身没错）。

## 条目统计

总计 **350** 条。

| 类别 | 含义                       | 条数 |
| ---- | -------------------------- | ---- |
| A    | 直接来自 XML 解析          | 279  |
| B    | 按 IDEA action id 人工指认 | 19   |
| C    | $default 物理键位兜底      | 49   |
| D    | 显式解绑                   | 3    |

**判定口径**（本表的分类是事后反推，不是原始生成日志）：

- A：preset 的键位都能在 `Mac OS X.xml` + `$default.xml` 解析出的「某个 IDEA action 的生效键位」里找到（子集关系），并可指名该 action。
- B：openidea action id 与 IDEA action id 不是同一个名字，靠人工按语义指认（例如 `toolwindow.project` ← `ActivateProjectToolWindow`）。
- C：两个 XML 里都找不到对应 action，preset 值是按 `$default.xml` 的物理键位落地；「无绑定」表示兜底后为空。**这批最可能有错，先看这一节。**
- D：IDEA 在 `Mac OS X.xml` 里列出该 action 却不给 keyboard-shortcut，即解绑；本表显示「无绑定」。

A 类里有 58 条键位虽然能在 XML 里找到，但对应的 IDEA action 语义不同，单独列在 A2 节，可靠性和 C 组接近。

A 类里的 IDEA action id 是「键位反查得到的最相近候选」，仅供参考；openidea 没有正式的 IDEA action id 映射表。备注里写「语义需人工确认」的，是键位对上了但两边 action 名字差得远，最可能语义配错。
